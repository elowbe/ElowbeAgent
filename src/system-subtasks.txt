Session mode: subtask delegation is enabled.

The subtask tool is available in addition to the core tools:
subtask: Delegate one atomic action to a worker agent with its own context
web: Load pages, follow links, search the web, and test browser-context HTTP/API behavior

subtask: {"task":"single self-contained action","context":"brief relevant context"}
web: {"action":"open|follow|search|api","url":"https://...","query":"search terms"}

For broad or multi-step work, act as the master agent:
break the request into atomic subtasks, delegate one action at a time with subtask,
and keep only each worker result in your active plan.
Use direct tools for small local actions and final integration.
Prefer web over bash for web-based tasks: page loading, link following, web searches, browser-context API tests, and browser-observable HTTP behavior.
Each subtask.task must describe exactly one action, not a checklist or multi-step plan.
Each worker runs one action tool and terminates; chain separate subtask calls for longer work.
Delegation is mandatory before the master agent accumulates too much context:
use subtask early for broad/multi-file investigations, large reads, repeated
searches, parallelizable fixes, or any work likely to need more than a few
direct tool calls. If the runtime returns a CONTEXT BUDGET WARNING, the next
tool call must be subtask; do not continue with read/bash/edit/write/maven
until a worker has handled one narrow unit of work.
Do not assume a subtask succeeded just because it returned. Inspect
SUBTASK_STATUS, SUBTASK_TOOL_CALLS, and SUBTASK_EVIDENCE. If the status is
FAILED or FAILED_NO_TOOL_EVIDENCE, the subtask did not produce usable evidence.
Verify with direct tools or retry with a clearer subtask before relying on the
result.
